# Stage-1 baseline (LightGBM), 2026-11-24

Diagnostic baseline for stage 1 of the classification pipeline: recognise the
*manifestation class* of a fault from the observable signature only. No tuning; the goal
is to see which classes the FI data can separate and which pairs need stage 3.

- Data: `ml/data/stage1_v0.parquet` (`ml/build_dataset.py`, from
  `logs/final-2026-11-05/dataset/runs.csv` incl. block 5 part 1). Labels: `ml/label_map.yaml`.
- Code: `ml/train_gbdt.py` (numbers in `baseline-2026-11-24.json`),
  `ml/render_report.py` (all tables and full confusion matrices in
  `baseline-2026-11-24-tables.md`). Out-of-fold probabilities of variant A: `oof_A.parquet`.
- Run time 150 s on the laptop CPU, no GPU.

## Definitions

- **Label.** GPR destination: functional unit that produced the value, from the opcode
  (unit output, pipeline latches and the register-file cell just written are
  architecturally indistinguishable). PR / UR / UP: register class, whatever the opcode.
  addr: address path at the moment of use (AGU and latches towards the LSU), memory
  descriptor included. mem_global / mem_shared: memory structure.
- **RAS excluded = detection mechanisms on protected structures** (ECC CE/UE counters,
  row remapping, power, GSP). They are zero by construction in FI, so they would leak.
  Xid 31/13/43 are execution exceptions that appear the same in FI and under beam: they
  are kept, as platform-neutral categories `mmu_fault` (31), `sm_exception` (13),
  `channel_stopped` (43), with counts.
- **Never inputs:** the injection record (opcode, PC, thread, CTA, SM, warp, lane, register,
  mask, values, MCU cells, addresses, store_wrong_location), location check, Masked
  subclasses, liveness weights, suspended_s, block, seed, hashes, run time (only the
  timeout flag is kept). Opcode, PC, workload and kernel are metadata for labels and splits.
- **Selection:** visible runs only (SDC, crash, timeout), `valid_for_rates = 1`, final-v1
  uniform group excluded (superseded by block 3), mode s included. fp16 (7 runs) and fp64
  (0) are not trained. Single bit → training/CV (22217 runs, 13 classes). MCU → separate
  test (14990 runs), expected class = single-bit class of the site.

## Setup

- **Features (49 `f_` + 6 `fw_`):** outcome one-hot; CUDA error (illegal address, illegal
  instruction, misaligned, unsupported address space, other); Xid flags and counts; on
  SDCs: log10 and fraction of wrong elements, fraction of outputs wrong, NaN/Inf
  fraction, log10 max and median relative error, bit class fractions, most significant
  changed bit, Hamming distance, fraction equal to the initial value (sfu_math only),
  fraction equal to another golden element, pattern one-hot, fraction of rows/columns,
  bounding box size and fill, clusters, aligned 16x16 tile, aligned warp of 32, rank of
  the difference (gemm, cnn), cnn images; kernels completed and completed-correct (apps
  with one output file per kernel: gemm, sfu_math). `fw_`: workload one-hot, log10 size.
- **Variants.**
  - **A** (operational): all `f_` + `fw_`.
  - **B** (physics test): no `fw_`, no `f_frac_eq_init`, `f_rank_log2`, `f_cnn_frac_images`,
    `f_partial_na`, `f_frac_kernels_completed`, `f_frac_outputs_wrong`.
  - **B2** (added): B without `f_frac_completed_correct` too. It reveals the workload in the
    same way (NaN by construction on cnn, ptr_chase, shm_stencil; on SDCs it equals
    1 − fraction of outputs wrong, i.e. 0.5 on gemm and 0.8 on sfu_math). It was missing
    from the B list; B is kept as defined, B2 measures what this feature carried.
- **CV:** `StratifiedGroupKFold`, 5 folds, groups = static site (registers: binary,
  kernel, PC; memory: binary, structure, buffer, 128-byte line). Stratified so that the
  classes with few sites land in several folds. LOWO (B, B2): train on 4 workloads, test on
  the 5th, only classes present in ≥ 2 workloads (mem_shared, sfu, tc excluded; up is in
  2 workloads, so it stays, see note in LOWO).
- **LightGBM:** multiclass, learning rate 0.05, 31 leaves, min 20 per leaf, feature and
  bagging fraction 0.9, balanced class weights, early stopping (50 rounds) on a
  site-grouped sixth of each training fold. Final model (SHAP, MCU test): all training, 27
  rounds (median of the folds).
- Early stopping stops at 26-34 rounds in every fold: validation sites are unseen sites,
  and the loss on them gets worse quickly. The model fits site-specific signatures
  that do not transfer to new sites (see per-fold F1 and LOWO).

What the numbers say:

1. **Stage 1 alone is weak on this data.** About 0.42 accuracy and 0.37 macro-F1 for SDCs
   and 0.24 for crashes, with sites never seen in training. It is well above chance, but
   most classes are not identifiable from the output signature alone.
2. **The workload one-hot adds almost nothing on SDCs** (A 0.366, B 0.363, B2 0.364).
   The output features already encode the workload. On crashes, A > B > B2: the only
   crash information beyond CUDA error and Xid is which kernel had finished, i.e. the
   workload and kernel.
3. **Nothing transfers across workloads.** LOWO SDC macro-F1 is 0.12-0.16, and most held-out
   SDCs are predicted `mem_global`. The signature of an SDC depends on the dataflow of the
   workload more than on the unit that produced the error. With 5 workloads the model
   cannot learn a workload-independent description.
4. **59% of SDCs have exactly one wrong element** (fp32 76%, int 84%, ld_data 79%, pr 69%,
   sfu and tc 100%). For these the only signal is the size and bit pattern of one value:
   single-element SDC macro-F1 0.33, accuracy 0.34.

55 descriptor runs in training, **all crashes** (descriptor flips never produced an SDC:
0 in all the campaigns). 41 are `ur` (LDCU of the descriptor, uniform group, persistent),
14 are `addr` (addr_part = desc, transient).

| true \ predicted | ur | ld_const | int | addr |
|---|---|---|---|---|
| ur (LDCU desc) | 26 | 15 | 0 | 0 |
| addr (desc) | 1 | 1 | 12 | 0 |

The expected ur ↔ addr confusion does not show up: 1 of 14 addr runs is predicted ur, 0 of
41 ur runs is predicted addr. The addr-descriptor crashes are predicted int, so the model
does not see them as "addr" either. With 55 runs, all crashes, this says little: the two
are not separated by physics but by other crash details of their workloads. Removing them
changes nothing (all-runs macro-F1 0.372 with and without). As decided, the descriptor
stays in ur.

## Conclusions for the pipeline

1. With these 5 workloads, stage 1 can recognise ur (warp-wide), mem_shared, sfu, tc and,
   to some extent, mem_global and ld_data. The last four are partly workload recognition.
2. **Crashes go to stage 3** except ur: CUDA error + Xid do not separate the other classes.
3. **pr cannot be learned from 10 sites.** A predicate flip manifests as a control-flow
   change of whatever it guards. It needs many more sites, or it should be treated as a
   stage-3 class from the start.
4. up and ur behave the same. Merge into one "uniform" class unless the beam separates them.
5. The result that matters most: **the signature does not transfer across workloads**
   (LOWO SDC macro-F1 0.12-0.16). The Orin campaign must add workloads, not only runs.
6. `oof_A.parquet` is ready for calibration and conformal prediction. Given top-2 accuracy
   0.61, prediction sets will be large for most SDCs. That is expected and is the
   input stage 3 needs.

## Requirements for the Orin campaign (collected so far)

1. **Every class in at least 2 workloads**, better 3+. Today tc (gemm), sfu (sfu_math) and
   mem_shared (shm_stencil) are in one workload and cannot be tested out of workload;
   up is in 2 with 61 runs.
2. **More workloads in total.** LOWO shows no transfer with 5 workloads. The signature is
   learned per workload.
3. **More static sites** for pr (10, all loop control), sfu (5), tc (10), up (6). Need
   workloads where predicates guard data (selects, boundary checks), several MUFU and MMA
   sites, and branches on warp-uniform conditions.
4. **MCU models on addresses** (groups 13 and 14): addr has no MCU test today.
5. **More MCU runs on tc** (7 today).
6. **Output buffers initialised with a sentinel value** in gemm, cnn, ptr_chase and
   shm_stencil (`cudaMalloc` only today, so "wrong element = initial value" cannot be
   computed; ptr_chase even allocates `out` after freeing `scale`). sfu_math already
   clears its buffer (0).
7. **One output file (or checksum) per kernel in every workload.** Today only gemm and
   sfu_math have one, so "kernels completed" is both a crash feature and a workload marker.
8. **fp16 and fp64 workloads** (no data today: 11 HFMA2 runs, 0 FP64).
9. Xid 31/13/43 mapped to the corresponding nvgpu messages on Orin
   (`mmu_fault`, `sm_exception`, `channel_stopped`).
10. Keep RAS features limited to execution exceptions (no ECC/remapping counters, which
    are zero by construction in FI).
11. Every workload logs base and size of every `cudaMalloc` in each run (observable under
    beam), for address features on the bases of that process (added 2026-11-25,
    `xid-features-2026-11-25.md`).
12. mem_injector writes the base address in the `alloc` events of `mem-profile.json`.
13. Check the address granularity of nvgpu fault messages on Orin (full address or page
    only) and whether SM exceptions report an address (here: Xid 31 page only, Xid 13 none).
14. Workloads whose known buffers cover a small part of the address region, so the
    address test stays informative (ptr_chase today: 51%).
